# Waybridge 3.5.2

Два канала между Linux-компьютерами в Tailscale:

- **Клиент → ПК:** снимок активного монитора; очередь в RAM; автоматическое открытие галереи на ПК.
- **ПК → клиент:** обычные файлы через ограниченный SFTP. Например, `main.py` появляется в `~/Documents/projects/main.py`.

Подмена клавиш, виртуальная клавиатура, захват устройств ввода, текстовые оверлеи и замена часов удалены. Батарея Waybar остаётся индикатором готовности связи; процент заряда настоящий.

## Простая установка

Нужны Arch/CachyOS, Hyprland с Lua-конфигурацией, Python 3.11+, systemd и работающий Tailscale на обоих компьютерах. Устройства должны видеть друг друга по Tailscale IPv4. Публичный IP и проброс портов не нужны. На ПК нужна графическая Wayland-сессия для imv.

Репозиторий приватный. У вашего Git-клиента должен быть доступ к нему. При использовании GitHub CLI один раз выполните `gh auth login` и `gh auth setup-git`.

На **обоих** устройствах из обычного терминала своей графической сессии:

```bash
git clone --branch v3.5.2 --depth 1 https://github.com/Archibald-42/waybridge.git
cd waybridge
bash setup.sh
```

Не запускайте `setup.sh` от root. Мастер сам вызывает sudo для системных шагов.

1. Выберите роль: **клиент** на ноутбуке, **сервер** на ПК.
2. Мастер установит зависимости и создаст публичный профиль в `~/Downloads/waybridge-ИМЯ-РОЛЬ.wbpair`.
3. Передайте этот профиль второму компьютеру через предложенный Taildrop. Приватные SSH-ключи не передаются.
4. Выберите полученный профиль противоположной роли и сверьте его код с экраном второго компьютера.
5. Подтвердите системную настройку паролем sudo. Повторите на втором устройстве.
6. Выполните `waybridge check` на обоих устройствах. Если команда не найдена в уже открытом терминале, откройте новый или используйте `~/.local/bin/waybridge check`.

Если второй профиль ещё не готов, выберите `q`: свой профиль уже сохранён. После его передачи повторите `bash setup.sh`.

**Установка с уже полученным профилем:**

```bash
bash setup.sh --role client --peer-profile ~/Downloads/server.wbpair --yes
# На ПК, с реально полученным профилем клиента:
bash setup.sh --role server --peer-profile ~/Downloads/client.wbpair --yes
```

Имена профилей в примере замените на фактические. `--yes` пропускает повторное подтверждение уже проверенного профиля; sudo и Tailscale-авторизация остаются штатными.

## Управление на клиенте

| Клавиша | Действие |
| --- | --- |
| Numpad 7 | Запустить транспорт |
| Numpad 8 | Снять активный монитор и отправить на ПК |
| Numpad 9 | Остановить транспорт, очередь и SFTP |

Привязки задаются в Hyprland по физическим кодам и не требуют чтения `/dev/input`. Клавиши Numpad 4/5/6 больше не используются Waybridge. Остальная клавиатура работает обычно.

```bash
waybridge start
waybridge stop
waybridge status
waybridge check
waybridge shot request
waybridge shot status
```

Numpad 8 можно нажимать несколько раз: снимки доставляются последовательно, до 8 заявок и 64 МиБ PNG в очереди. При переполнении новая заявка отклоняется; уже принятые продолжают отправляться. При остановке содержимое RAM-очереди теряется.

На ПК изображения открывает `imv-wayland`. Закрытие окна не останавливает приёмник: следующий новый снимок вновь откроет галерею. В ней сохраняются последние 50 снимков. Клавиша `x` закрывает окно целиком; удаление отдельных элементов обходится безопасным алгоритмом, совместимым с imv 5.0.1.

## Передача файлов с ПК

В новом терминале ПК доступны короткие команды:

```bash
wbs ~/Documents/main.py                  # один файл
wbs main.py input.txt config.json        # несколько файлов подряд
wb-send main.py                         # полное имя той же команды
wb-send-as other.py main.py              # отправить под именем main.py
wb-files                                # список файлов во входящей папке клиента
```

Папка назначения на ноутбуке: `~/Documents/projects`. Если полный путь содержит пробелы, заключите его в кавычки; само имя передаваемого файла должно соответствовать правилам ниже. Все исходные файлы остаются на ПК. Команда `wbs` сначала проверяет все аргументы, затем отправляет по очереди и печатает подтверждение каждой загрузки. Если ошибка сети произошла посередине, ранее отправленные файлы сохраняются — пакет не является общей транзакцией.

Для старых сценариев сохранены `send-code ФАЙЛ`, `waybridge send-code ФАЙЛ --name ИМЯ`. Без коротких команд: `waybridge send-files ФАЙЛ...` и `waybridge remote-files`.

Файл загружается как временный SFTP-объект и атомарно переименовывается. Затем клиент подтверждает запись в папку projects: ответ содержит UUID именно этой отправки и SHA-256. Успех команды означает сохранение на клиенте, а не только загрузку в SFTP. При ошибке содержимое исходника на ПК сохраняется. На клиенте inotify переносит завершённую версию в `~/Documents/projects` под исходным именем. Файлы не исполняются и не вводятся в другие приложения.

Имена: ASCII, буквы/цифры/точка/дефис/подчёркивание, до 101 символа. Один файл — до 32 МиБ. Поддерживаемые расширения: `.py .cpp .c .h .hpp .rs .js .ts .java .go .sh .txt .json`.

При перезаписи старое содержимое сохраняется в `~/.cache/bridge/versions`. Символические ссылки из входящей папки отклоняются. Файлы `clock.txt` и `answer.txt` больше не управляют интерфейсом; после миграции это обычные текстовые файлы.

## Батарея и часы

- Часы Waybar показывают настоящее системное время обычным модулем `clock`.
- Процент батареи остаётся настоящим. Синеватый оттенок — локальные службы работают, ПК online в Tailscale и его SSH-приёмник отвечает. Красноватый — транспорт остановлен или соединение не готово.
- Проверка доступности приёмника выполняется не чаще раза в 15 секунд. Оттенок не является подтверждением доставки конкретного снимка. Доставка фиксируется отдельно по проверенному ACK в журнале очереди.
- На компьютере без батареи выводится `АКБ —`.

## Архитектура и ограничения

```text
Клиент: grim → ограниченная RAM-очередь → SSH:2223 → ПК: проверка PNG → галерея imv
ПК: send-code → SFTP:2222 → клиент: chroot /inbox → inotify → ~/Documents/projects
```

`grim` пишет PNG в stdout; на клиенте файл снимка и буфер обмена не используются. Монитор выбирается через Hyprland. Для захвата остаётся явное разрешение screencopy для grim в конфигурации композитора.

Протокол PNG содержит случайный ID, размер и SHA-256. Приёмник проверяет структуру PNG/CRC и размер, сохраняет атомарно с fsync и возвращает ACK. Повторная передача того же ID с тем же содержимым не создаёт дубликат; конфликт ID отклоняется. До 3 попыток по 30 секунд. Максимум PNG — 32 МиБ.

Приёмник файлов — отдельный sshd, учётная запись `bridge`, chroot `/srv/bridge`, только internal-sftp, без shell, TTY и forwarding. Приёмник снимков — отдельный sshd с forced command. Оба слушают только свой Tailscale IPv4; nftables ограничивает соответствующий порт интерфейсом `tailscale0` и IP второго ПК. Общие правила firewall не сбрасываются.

Приватные SSH-ключи создаются локально. Host key второго компьютера закрепляется по проверенному публичному профилю. Предупреждения о смене ключа нельзя обходить отключением проверки.

На клиенте работают только:

```text
bridge-shot-queue.service  — пользовательская очередь снимков
bridge-files.service       — пользовательская доставка файлов в projects
bridge-inbox.service       — системный ограниченный SFTP
bridge-filter.service      — системный фильтр входящего порта
```

На ПК: `bridge-shot.service`, `bridge-shot-view.service`, `bridge-filter.service`.

Старт endpoints управляется графической сессией. После явной остановки ставится маркер `stopped`; следующий вход не запускает транспорт до явного `start`. Tailscale и остальные программы остановка Waybridge не затрагивает.

## Зависимости и установка без pip

Мастер устанавливает через pacman:

- Общие: `python tailscale openssh nftables inotify-tools`.
- Клиент: `acl grim waybar`.
- ПК: `imv`.

`ydotool`, доступ к `/dev/uinput` и ACL клавиатуры больше не нужны. Python-библиотек из PyPI нет. `scripts/bootstrap.py` создаёт venv без pip и устанавливает исходники в отдельный каталог версии; запуск переключается атомарно.

Локальная конфигурация: `~/.config/waybridge/config.toml`. Она содержит роль, own/peer Tailscale IPv4, имена пользователей и при необходимости пути `inbox`, `projects`, `state`, лимиты `queue_count`, `queue_bytes`, `png_limit`. Выбор клавиатуры отсутствует. Входящая папка root-установщика фиксирована: `/srv/bridge/inbox`.

## Обновление и смена ПК

Обновите checkout до нужного тега и выполните `bash setup.sh` ещё раз. Мастер удалит retired-компоненты старых версий: службы ввода/подсказок, клавиатурное ACL-правило, root-демон виртуальной клавиатуры, старые команды и подмену часов. Батарея-индикатор остаётся.

Для нового ПК повторите простую установку и обменяйтесь новыми публичными профилями на обоих устройствах. Не переносите приватные ключи. Для смены ролей выберите противоположные роли на обоих устройствах; мастер пересоздаст ограничение порта/peer и интеграцию. На роли сервера обычная батарея восстанавливается.

## Полное удаление и установка с нуля

```bash
waybridge uninstall
```

Введите `yes`, затем пароль sudo. Удалятся службы, dedicated SSH-конфигурация и ключи, правила Waybridge, его учётная запись `bridge`, установленный Python runtime и интеграция. Общие пакеты, Tailscale, системные SSH host keys и стандартный sshd не удаляются.

`~/Documents/projects` сохраняется. Входящие файлы, снимки и история версий копируются в `~/.local/state/waybridge-preserved/ВРЕМЯ`. Исходный Git checkout тоже сохраняется. Удаление не требует удалять пользовательские документы.

После удаления для чистой установки снова выполните команды из раздела «Простая установка». Профили создаются заново: старые dedicated ключи удалены.

## Диагностика

```bash
waybridge check
waybridge status
journalctl --user -u bridge-shot-queue.service -u bridge-files.service -n 80 --no-pager
systemctl status bridge-inbox.service bridge-filter.service
# На ПК:
journalctl --user -u bridge-shot-view.service -n 80 --no-pager
systemctl status bridge-shot.service
```

- Numpad не запускает: `hyprctl configerrors`, наличие `dofile` для `~/.config/bridge/hypr-client.lua`, затем `waybridge start` для подробной ошибки.
- ПК offline: проверьте питание, `tailscale status` и адрес peer.
- SSH-ошибка ключа: перепройдите `setup` с актуальными проверенными профилями.
- Снимок не доставлен: журнал очереди содержит `delivery confirmed` либо `delivery failed` и ID. Очередь ограничена; она не хранится на диске.
- Галерея не появилась: проверьте пользовательский `bridge-shot-view.service` и Wayland-переменные в `systemctl --user show-environment`.
- Файл не появился: проверьте расширение/имя/размер и `bridge-files.service`; просмотр только завершённых загрузок.
- Ошибки доступа к клавиатуре больше не участвуют в запуске: программный ввод полностью удалён.

## Разработка и проверка релиза

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
python -W error -m compileall -q src scripts
bash -n setup.sh
python scripts/release.py --output ../waybridge-3.5.2.tar.gz
sha256sum -c SHA256SUMS
```

Тесты проверяют протокол, повторную доставку, границы очереди/файлов, атомарное сохранение, галерею, pairing, установщик и удаление retired-функций. CI запускается на Python 3.11 и 3.14. Живая проверка обоих устройств описывается отдельно в `docs/VALIDATION.md`.

Исходники, ключи и данные разделены. Не публикуйте профили, конфигурацию, private keys, входящие файлы или снимки. `scripts/release.py` использует явный список исходных каталогов и не добавляет runtime-данные.

## Надёжность в 3.5.2

- Роли называются `client` / `server`. Файл автозапуска ПК — `hypr-server.lua`, команда — `server-start`. Старые значения роли и пользователя читаются для совместимости и переводятся при миграции; приватные ключи менять не требуется.
- Перед запуском проверяются зависимости, графическая сессия, собственный адрес Tailscale и возможность записи в рабочие каталоги. Клавиатура, evdev и uinput не участвуют.
- Файловый обработчик и галерея подтверждают готовность через systemd notify. Запуск проверяет службы и RPC очереди; при сбое откатывает транспорт в остановленное состояние.
- Остановка работает независимо от графической сессии и доступности сети. Статус не ждёт блокировку запуска; операции управления ограничены временем ожидания.
- Ошибка одного входящего файла записывается в журнал и подтверждение отправки; другие файлы продолжают обрабатываться. Исправив причину, повторите отправку. Неудачная заявка сохраняется для диагностики и повторной обработки при перезапуске.
- Входящая папка содержит служебные `.delivery-UUID.json` и `.receipts/UUID.json`. Подтверждение связано с конкретной отправкой и хешем. История подтверждений ограничена 256 записями. Обновите оба устройства для нового подтверждаемого протокола файлов.
- `waybridge shot status` показывает последний подтверждённый снимок, число доставленных снимков и последнюю ошибку.

Локальная персонализация скорости сети в Waybar сохраняется при обновлении; она не возвращает доступ к клавиатуре или замену часов.
