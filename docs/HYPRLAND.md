# Hyprland: .conf, .lua и обновление

Начиная с Waybridge 3.6.3 установщик поддерживает оба формата без переноса
пользовательских настроек из одного языка в другой.

## Выбор активного конфига

- Если существует только `~/.config/hypr/hyprland.conf`, выбирается `.conf`.
- Если существует только `~/.config/hypr/hyprland.lua`, выбирается `.lua`.
- Если ранее выбор был сохранён и файл существует, используется сохранённый путь.
- Если существуют оба файла и сохранённого выбора нет, мастер останавливается
  до изменений служб и просит `--hypr-config`.
- Нестандартный основной файл можно указать тем же параметром.
- Если основной файл не найден, мастер сообщает о необходимости ручного подключения.
  Чтобы полностью пропустить интеграцию с Hyprland и Waybar, используйте `--no-integrate`.

```bash
bash setup.sh --role server --hypr-config ~/.config/hypr/hyprland.conf
# Обновление существующей пары:
bash setup.sh --update --hypr-config ~/.config/hypr/hyprland.conf
# Последующие обновления используют сохранённый выбор:
bash setup.sh --update
```

Путь хранится в `hypr-integration.json` рядом с конфигурацией Waybridge.
Если вы сменили активный формат, но старый файл ещё существует, укажите новый явно.
Установщик не угадывает активность файла по его дате изменения.

## Что подключается

В `.conf` сервера:

```ini
# Waybridge session module
source = ~/.config/bridge/hypr-server.conf
```

В `.lua` сервера:

```lua
-- Waybridge session module
dofile(os.getenv("HOME") .. "/.config/bridge/hypr-server.lua")
```

Клиент использует аналогичные `hypr-client.conf` / `hypr-client.lua`.
Оба набора модулей создаются установщиком, но подключается один выбранный.
Модуль сервера содержит запуск `server-start` при входе в Hyprland;
клиентский — запуск обработчиков, сочетания Win+Z/X/A и разрешение screencopy для grim.
Конфигурация `.conf` использует документированный Hyprlang-синтаксис Hyprland 0.54;
для существенно более старого клиента проверьте поддержку `permission` в его версии.
На сервере разрешение screencopy не добавляется.

При смене роли или формата установщик убирает свои прежние подключения из
известных файлов. Другие `source`, `dofile`, настройки и комментарии остаются.
Повторное обновление не создаёт дублирующих подключений. Перед изменением
файлы сохраняются в `~/.local/state/waybridge/backups/`.
Симлинки на dotfiles сохраняются; резервируется и изменяется целевой файл.
Недоступный для записи файл требует ручной интеграции с `--no-integrate`.

## Когда срабатывает автозапуск

`exec-once` срабатывает при следующем запуске compositor, а не при обычном reload.
В текущей сессии мастер отдельно запускает транспорт, если не передан `--no-start`.
Явная команда `waybridge stop` сохраняет остановку до команды `waybridge start`.
Установщик не включает автоматический вход в SDDM и не создаёт графическую сессию.

На клиенте изменения разрешения screencopy могут требовать перезапуска Hyprland;
разрешение применяется по правилам compositor, а не обходится установщиком.

## Удаление

`waybridge uninstall` удаляет собственные подключения из стандартных `.conf`/`.lua`
и запомненного пользовательского файла, затем удаляет каталог собственных модулей.
Другие подключения в конфиге сохраняются; симлинки не заменяются обычными файлами.

Синтаксис: [source и exec-once](https://wiki.hypr.land/0.54.0/Configuring/Keywords/),
[привязки клавиш](https://wiki.hypr.land/0.54.0/Configuring/Binds/),
[разрешения](https://wiki.hypr.land/0.54.0/Configuring/Permissions/).
